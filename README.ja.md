# ◒ TraceVeil

### ログの流れは、そのまま。見せたくない値は、伏せる。

**GitHubのIssue、チームへの相談、AIへの質問。その前にログを整える、無料のローカルツールです。**

[ブラウザで試す](https://shiro-gg0711.github.io/traceveil/) · [単体HTML](https://github.com/shiro-gg0711/traceveil/blob/main/dist/TraceVeil.html) · [English](README.md) · [更新履歴](CHANGELOG.md)

```text
入力                               出力
alice@example.test failed           [EMAIL_1] failed
token=fictional-value               token=[SECRET_1]
alice@example.test retried          [EMAIL_1] retried
  at login (auth.js:42:7)             at login (auth.js:42:7)
```

同じ値には同じラベルを付けるので、誰が再試行したか、どのクライアントで失敗したかを追えます。改行とスタックトレースの行番号を残します。

## まず30秒で試す

**配布ZIPの単体HTML版なら、Node.jsのインストールは不要です。**

1. `dist/TraceVeil.html` をブラウザで開きます。
2. 「サンプルを試す」を押すか、ログを貼り付けます。
3. 結果を確認します。社名やホスト名なども伏せたい場合は「名前・ホスト名…」を開いて値を追加します。
4. 「結果をコピー」「GitHub用にコピー」「.txtを保存」で共有用の内容を取り出します。

アカウント・APIキー・外部ライブラリは不要です。ログをアップロードせず、このブラウザ内で処理します。アクセス解析や入力の永続保存もありません。公開デモには初回のページ読み込みが必要ですが、HTMLを保存すればコードとスタイルをまとめて持ち運べます。

ソースから使う場合は[Node.js24以上](https://nodejs.org/en/download)を用意して、次を実行します。

```sh
node cli.mjs --web
```

表示されたURLを開いてください。Windowsでは `start.cmd` のダブルクリックでも起動します。単体HTMLを生成するコマンドは `node scripts/build.mjs`。`npm install` は不要です。

## 日常の使いどころ

| したいこと | 操作 |
| --- | --- |
| GitHubへ不具合を報告 | ログを貼り付け、確認して「GitHub用にコピー」。コードブロックに整えてコピーします。 |
| AIにエラーの原因を相談 | 行番号や呼び出しの流れを残しながら、対応するメール・認証値などを伏せます。 |
| チームに内部ログを共有 | 社名、プロジェクト名、ホスト名などを追加値に入れ、結果を確認します。 |
| スクリプトでログを確認 | `--check` で本文を出さずに検出件数と終了コードを取得します。 |

日本語・英語の自動切替、明暗テーマ、ファイル選択・ドロップ、種類別の件数、バックグラウンド処理に対応します。処理中はコピー・保存を無効化し、古い結果が新しい入力に混ざらないようにしています。

### 自分で伏せたい値を追加

1行に1つ入力します。大文字・小文字を区別した完全一致で、各2〜256文字、最大32個です。追加値同士や自動検出と重なる部分は、まとめて伏せます。既に作られたラベルは壊しません。表示件数は、重なりをまとめた後の伏せ字の数です。正規表現や自動の人名検出ではありません。

「すべて消去」で元ログと追加値を画面から消し、処理も中断します。既にコピーした文字列・保存ファイル・ブラウザ側の履歴は消しません。

## ターミナルでも使う

```sh
node cli.mjs examples/debug.log
node cli.mjs debug.log --output redacted.log
node cli.mjs --check debug.log
node --test
```

入力はUTF-8・8 MiBまで。元ファイルも既存の出力先も上書きしません。PowerShellでは文字コードの差を避けるため `>` より `--output` を使ってください。

終了コードは通常 `0`、`--check` で対象を検出した場合 `1`、操作エラーは `2`。追加値はブラウザ版とライブラリAPIで使えます。CLIは自動検出を行います。

## 検出範囲と限界

一般的なメール・IPv4・APIキーやパスワードなどの代入・Bearer/Basic認証・一部の既知トークン・URL認証・完全なPEM秘密鍵に対応します。

**すべての秘密情報を検出するものではありません。共有前に必ず確認してください。** IPv6・Cookie・氏名・住所・ホームパス・独自形式・エンコード済みの値・任意の複数行の秘密情報は網羅しません。必要な場合は追加値を指定してください。誤検出もあります。同じラベルから値の一致は分かるため、暗号学的な匿名化ではありません。認証情報の無効化や、元ファイル・クリップボード・保存結果の保護は行いません。詳細は[英語版の検出仕様](README.md#what-it-catches)に記載しています。

## 公開・開発

[ソース](https://github.com/shiro-gg0711/traceveil)と[公開デモ](https://shiro-gg0711.github.io/traceveil/)を公開しています。[公開手順](docs/PUBLISHING.md)には、自分のフォークを公開・更新する方法をまとめました。Issueテンプレート、テスト設定、MITライセンスも同梱しています。npmへの公開や告知の送信は行いません。

GitHub上のCIは、Windows・macOS・LinuxとNode.js 24／26の全6環境で成功しました。公開デモも組み込みChromiumブラウザで確認しています。単体HTMLはHTTP配信で検証済みです。自動ブラウザは `file://` への移動を許可しないため、その環境ではファイル直接起動を確認できていません。

ログを伏せる既存ツールはあります。本作は、関係性を残すラベル・読み解ける共通エンジン・導入不要の単体版に重点を置いています。世界初や完全な安全性をうたうものではありません。
